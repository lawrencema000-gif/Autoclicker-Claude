Allow Auto Clicker to tap your screen (one-time setup) 2. Choose your mode and press START 3. Pick your target points on screen 4. Auto Clicker runs automatically — pause, resume, or stop anytime No root required. Your scripts and data stay on your device — nothing is uploaded. 14. Accessibility service declaration

Why does your app need the Accessibility Service permission?

Auto Clicker uses the Accessibility Service to perform automated touch gestures (taps, swipes, long-presses) at user-defined screen coordinates. This is the core function of the app — automating repetitive screen interactions that the user has explicitly configured. The Accessibility Service is used ONLY to: 1. Dispatch touch gestures via dispatchGesture() at user-specified coordinates 2. Display overlay controls (floating toolbar, picker, crosshair) over other apps 3. Detect volume key presses for the optional start/stop trigger feature The Accessibility Service is NOT used to: - Read any screen content, text, or UI elements - Monitor the user's activity in other apps - Collect or transmit any data - Auto-fill, type, or enter any text Users explicitly enable this permission during onboarding, with a clear explanation of what it does. The functionality cannot be achieved through any other Android API. This is the standard mechanism used by all legitimate auto-clicker apps on the Play Store, as Android does not provide an alternative API for programmatic gesture dispatch.

15. Foreground service special use declaration

Why does your app use FOREGROUND_SERVICE_SPECIAL_USE?

Auto Clicker uses a foreground service to keep the auto-clicking session running while the user navigates to and interacts with other apps on their device. The user must be able to switch to a target app (game, utility, etc.) while the click sequence continues to execute. We use foregroundServiceType="specialUse" with subtype "automation" because: - The app's core function is user-controlled task automation - Existing foreground service types (mediaPlayback, location, etc.) do not match this use case - The service runs only while the user has explicitly started a click session - A persistent notification with stop/pause controls is shown the entire time the service runs - The session automatically stops when the user presses Stop, when the screen turns off (configurable), or after the configured stop condition is met The service does NOT run in the background indefinitely. It is bound 1:1 to the active click session that the user explicitly started.
